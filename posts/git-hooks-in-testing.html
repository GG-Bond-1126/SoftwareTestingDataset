Git Hooks：测试脚本提交前的自动检查

环境搭建

terminal
# 安装 Git
# 配置用户
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
# 验证
git --version
terminal — 初始化仓库
mkdir my-project && cd my-project
git init
echo "hello" > test.py
git add .
git commit -m "初始提交"

基础应用：分支操作

terminal
# 创建 + 切换分支
git checkout -b dev
git commit -m "dev 修改" --allow-empty
git checkout main
git merge dev

# 查看日志
git log --oneline --graph

项目进阶：Feature 分支 + MR 流程

terminal
# Feature 分支
git checkout -b feature/login
git commit -m "feat: 用户登录" --allow-empty

# 提 MR（在 GitHub/GitLab 上）
# 评审通过后合并
git checkout main
git pull origin main
git merge --squash feature/login
git commit -m "feat: 用户登录"
git push origin main
git branch -d feature/login

hook 是什么、在哪

hook 就是「Git 在某个节点自动执行的脚本」。比如 pre-commit（提交前）、post-merge（合并后）。脚本放在 .git/hooks/ 目录下，每个文件对应一个节点。

terminal — 查看可用的 hook
# 查看所有可用的 hook 脚本（默认是 .sample 后缀的模板）
ls .git/hooks/

# 最实用的几个：
# pre-commit     提交前执行，失败则取消提交
# pre-push       推送前执行，失败则取消推送
# post-merge     合并后执行（更新依赖、重新安装等）
# post-checkout  切换分支后执行

hook 是本地的，不会随着 clone 分发。团队共享 hook 的方式：把脚本放在仓库里的 scripts/hooks/，然后用 core.hooksPath 配置 Git 去读那个目录。

团队共享 hook 的方法

这是测试团队最该知道的——「每人自己配一遍」太脆弱：

terminal — 配置共享 hook 目录
# 1. 在仓库里建一个目录放 hook 脚本
mkdir -p scripts/hooks
# 把 pre-commit、post-merge 脚本放进 scripts/hooks/

# 2. 配置 Git 去读这个目录（每个开发/测试本地执行一次）
git config core.hooksPath scripts/hooks

# 3. 把 scripts/hooks/ 目录提交到仓库
git add scripts/hooks/
git commit -m "chore: 添加 Git hooks 脚本"
git push

# 4. 新同事 clone 后只需执行一次
git config core.hooksPath scripts/hooks

在仓库的 CONTRIBUTING.md 里写清楚这条配置命令，新人 clone 后执行一次，之后所有 hook 自动生效。

pre-commit：提交前自动检查

测试仓库里，提交前应该检查什么？至少三条：代码风格、明显错误、敏感信息。

scripts/hooks/pre-commit（Python 测试仓库示例）
#!/bin/bash
# 测试仓库提交前检查

echo "=== 检查代码风格 ==="
# 只检查本次提交涉及的文件（比全量检查快）
git diff --cached --name-only --diff-filter=dACMR \
  | grep -E '\.py$' \
  | xargs -r flake8 --max-line-length=120

if [ $? -ne 0 ]; then
    echo "❌ 代码风格检查失败，提交已取消"
    exit 1
fi

echo "=== 检查明显错误 ==="
# 检查是否误提交了调试代码
if git diff --cached | grep -qE '(print\("DEBUG|breakpoint\(|pdb\.set_trace\()'; then
    echo "❌ 检测到调试代码，请清理后再提交"
    exit 1
fi

echo "=== 检查敏感信息 ==="
# 检查是否误提交了 API key
if git diff --cached | grep -qE '(api_key\s*=|secret\s*=|password\s*=).{10,}'; then
    echo "❌ 检测到疑似敏感信息，提交已取消"
    exit 1
fi

echo "✅ 检查通过，可以提交"

pre-commit 脚本必须用 exit 1 才能阻止提交。如果脚本执行成功（exit 0），提交正常进行。

pre-push：推送前跑关键测试

比 pre-commit 更严格，可以跑「快但关键」的测试：

scripts/hooks/pre-push
#!/bin/bash
# 推送前跑冒烟测试（快但关键的）

echo "=== 推送前冒烟测试 ==="
python -m pytest tests/smoke/ -x --tb=short

if [ $? -ne 0 ]; then
    echo "❌ 冒烟测试失败，推送已取消"
    echo "提示：可以用 git push --no-verify 跳过（仅限紧急场景）"
    exit 1
fi

echo "✅ 冒烟测试通过，可以推送"

pre-push 跑完整测试太慢（几百条用例要 20 分钟），只跑冒烟测试。完整测试交给 CI/CD 跑。

post-merge：合并后自动更新

合并后自动重装依赖、更新测试数据，不用手动操作：

scripts/hooks/post-merge
#!/bin/bash
# 合并后自动执行

echo "=== 合并后自动更新 ==="

# 1. 重装 Python 依赖（requirements.txt 可能变了）
if [ -f "requirements.txt" ]; then
    echo "重新安装依赖..."
    pip install -r requirements.txt
fi

# 2. 如果有虚拟环境，激活并更新
if [ -d "venv" ]; then
    source venv/bin/activate
    pip install -r requirements.txt
fi

# 3. 更新测试数据（如果配置了数据同步脚本）
if [ -f "scripts/sync_test_data.sh" ]; then
    bash scripts/sync_test_data.sh
fi

echo "✅ 合并后自动更新完成"

其他实用 hook

post-checkout — 切分支后自动处理
#!/bin/bash
# 切分支后自动安装对应依赖
NEW_BRANCH="$1"

if [ "$NEW_BRANCH" = "main" ] || [ "$NEW_BRANCH" = "develop" ]; then
    echo "=== 切到 $NEW_BRANCH，更新依赖 ==="
    pip install -r requirements.txt
fi

echo "=== 当前分支：$NEW_BRANCH ==="

hook 的常见坑

  • hook 没加执行权限：Linux/Mac 上必须 chmod +x .git/hooks/pre-commit，否则 Git 会跳过。
  • hook 太慢：每次提交等 30 秒 lint，团队会绕开 hook。控制在 10 秒内，慢检查放 CI。
  • Windows 下 hook 不生效：Windows Git 默认不执行 hook，需要在 Git 设置里打开「Enable Git hooks」。

hook 是「本地守门员」，CI 是「团队守门员」。本地 hook 快、便宜、能拦住 80% 的问题；CI 兜底、全面、拦住剩下 20%。两者配合才是完整的质量关卡。
