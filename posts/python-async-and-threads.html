为什么测试脚本需要并发

测试脚本 90% 的时间花在「等」上：等接口响应、等页面加载、等数据生成。串行跑（一条跑完跑下一条）时，这些「等」全在浪费时间。并发（多条同时跑）把「等」重叠起来，总耗时大幅缩短。

串行 vs 并发耗时对比
# 100 条用例，每条等接口 0.5 秒
# 串行：100 × 0.5s = 50s
# 并发 10 线程：ceil(100/10) × 0.5s = 5s
# 并发 20 线程：ceil(100/20) × 0.5s = 2.5s

# 100 条用例，每条跑 3 秒（含业务逻辑）
# 串行：100 × 3s = 300s（5 分钟）
# 并发 10 线程：ceil(100/10) × 3s = 30s（30 秒）

threading：多线程（IO 密集型首选）

测试脚本是IO 密集型（等网络、等磁盘），不是 CPU 密集型（算数据）。IO 密集型用多线程就够了，不用管 GIL。

基本用法

python — 基本多线程
import threading
import time

def call_api(user_id):
    """模拟调用接口（等 1 秒）"""
    time.sleep(1)   # 模拟网络延迟
    print(f"  用户 {user_id} 数据获取完成")
    return user_id

# 创建 5 个线程，同时调用
threads = []
for i in range(5):
    t = threading.Thread(target=call_api, args=(i,))
    threads.append(t)
    t.start()

# 等待所有线程完成
for t in threads:
    t.join()   # 阻塞当前线程，等 t 结束

print("全部完成")
# 5 个线程同时跑，总耗时约 1 秒（不是 5 秒）

线程池（更实用）

手动管理线程太麻烦，用线程池「控制并发数 + 自动回收」：

python — 线程池
from concurrent.futures import ThreadPoolExecutor, as_completed
import time

def call_api(user_id):
    """模拟调用接口"""
    time.sleep(0.5)   # 等 0.5 秒
    return f"user_{user_id}_data"

# 创建线程池（10 个线程并发）
with ThreadPoolExecutor(max_workers=10) as executor:
    # 提交 100 个任务
    futures = {
        executor.submit(call_api, i): i
        for i in range(100)
    }

    # 收集结果（按完成顺序）
    results = []
    for future in as_completed(futures):
        user_id = futures[future]
        result = future.result()   # 拿结果（异常在这里抛）
        results.append(result)

print(f"共 {len(results)} 条结果")
# 总耗时约 5 秒（100 条 / 10 线程 × 0.5 秒）

线程池的三个参数：max_workers（并发数，测试里一般 10~50）、as_completed（按完成顺序拿结果）、future.result()（拿结果，异常在这里抛）。比手动创建线程简洁 10 倍。

GIL 限制：CPU 密集型用多进程

python — 多进程（CPU 密集型）
from concurrent.futures import ProcessPoolExecutor
import time

def heavy_computation(data):
    """CPU 密集型（算数据）"""
    result = 0
    for i in range(10_000_000):
        result += i
    return result

# 多线程跑 CPU 密集型（受 GIL 限制，不会更快）
# 多进程跑 CPU 密集型（每个进程独立 GIL，真正并行）
with ProcessPoolExecutor(max_workers=4) as executor:
    futures = [executor.submit(heavy_computation, i) for i in range(8)]
    for f in futures:
        print(f.result())

测试脚本 99% 是 IO 密集型（等接口），用多线程就够了。只有「跑大量计算」（比如性能测试数据分析）才需要多进程。

asyncio：异步（高并发 IO 首选）

线程池是「10 个线程各等各的」，asyncio 是「1 个线程轮流处理」。并发 1000 个请求时，asyncio 比 1000 个线程省内存得多。

基本用法

python — asyncio 基础
import asyncio

async def call_api(user_id):
    """模拟调用接口（等 0.5 秒）"""
    await asyncio.sleep(0.5)   # 异步等（不阻塞其他任务）
    return f"user_{user_id}_data"

async def main():
    # 并发 100 个请求（asyncio 自动切换）
    tasks = [call_api(i) for i in range(100)]
    results = await asyncio.gather(*tasks)   # 等全部完成
    print(f"共 {len(results)} 条结果")
    # 总耗时约 0.5 秒（所有任务"同时"等，轮流完成）

# 运行
asyncio.run(main())

并发控制（信号量）

1000 个请求同时打接口，服务器会崩。用信号量控制「同时最多 50 个」：

python — 信号量控制并发
import asyncio
import aiohttp   # 异步 HTTP 客户端（pip install aiohttp）

async def fetch(url, session, semaphore):
    async with semaphore:   # 同时最多 50 个请求
        async with session.get(url, timeout=10) as resp:
            return await resp.text()

async def main():
    semaphore = asyncio.Semaphore(50)   # 最多 50 并发
    urls = [f"https://api.example.com/data/{i}" for i in range(1000)]

    async with aiohttp.ClientSession() as session:
        tasks = [fetch(url, session, semaphore) for url in urls]
        results = await asyncio.gather(*tasks)

    print(f"共 {len(results)} 条结果")

asyncio.run(main())
# 1000 个请求，50 并发，总耗时约 10 秒（20 批 × 0.5 秒）

线程池 vs asyncio 怎么选

选择标准
# 并发数 10~100 → 线程池（ThreadPoolExecutor）简单够用
# 并发数 1000+ → asyncio（省内存、不爆线程）
# 代码复杂度 → 线程池更简单，asyncio 要理解 await 和协程
# 测试场景 → 一般 10~50 并发就够，线程池是首选

案例：并发调用接口 + 结果收集 + 统计

把线程池 + 结果收集 + 统计串起来，写一个「并发跑 100 条用例」的完整模板：

python — 并发测试完整模板
from concurrent.futures import ThreadPoolExecutor, as_completed
import time
import requests
from dataclasses import dataclass
from typing import Optional
import json

@dataclass
class TestResult:
    """测试结果"""
    case_id: int
    name: str
    passed: bool
    response_ms: Optional[int]
    error: Optional[str]

def run_single_case(case):
    """跑单条用例（线程池里执行）"""
    try:
        start = time.time()
        resp = requests.get(
            f"https://api.example.com/api/{case['endpoint']}",
            timeout=10
        )
        response_ms = int((time.time() - start) * 1000)

        passed = resp.status_code == case.get("expected_status", 200)
        if not passed:
            error = f"状态码 {resp.status_code} != {case.get('expected_status')}"
        else:
            error = None
        return TestResult(case["id"], case["name"], passed, response_ms, error)
    except Exception as e:
        return TestResult(case["id"], case["name"], False, None, str(e))

def run_cases_concurrent(cases, max_workers=10):
    """并发跑所有用例（线程池）"""
    results = []
    with ThreadPoolExecutor(max_workers=max_workers) as executor:
        futures = {
            executor.submit(run_single_case, case): case
            for case in cases
        }
        for future in as_completed(futures):
            results.append(future.result())

    # 按 case_id 排序
    results.sort(key=lambda r: r.case_id)
    return results

# 100 条用例（模拟）
test_cases = [
    {"id": i, "name": f"用例 {i}", "endpoint": f"/data/{i}", "expected_status": 200}
    for i in range(100)
]

# 跑
start = time.time()
results = run_cases_concurrent(test_cases, max_workers=10)
total_time = time.time() - start

# 统计
passed = sum(1 for r in results if r.passed)
failed = len(results) - passed
avg_ms = sum(r.response_ms or 0 for r in results) / len(results)

print(f"总耗时：{total_time:.1f}s")
print(f"通过：{passed}/100，失败：{failed}")
print(f"平均响应：{avg_ms:.0f}ms")

# 打印失败用例
for r in results:
    if not r.passed:
        print(f"  失败：{r.name} - {r.error}")

测试并发三原则：① IO 密集型用线程池（10~50 并发）；② 高并发用 asyncio（1000+）；③ 加信号量控制并发数，别让服务器崩。100 条用例并发 10 线程，30 分钟降到 5 分钟。
