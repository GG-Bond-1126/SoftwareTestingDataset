测试时怎么跨表查数据：JOIN 的四种姿势一次讲透

mysql -h localhost -u root -ptest123 testdb

项目进阶：并发测试 + 数据一致性

python
import mysql.connector, threading

def deduct(uid, qty):
    c = mysql.connector.connect(host="localhost", user="root", password="test123", database="testdb")
    cur = c.cursor()
    cur.execute("UPDATE products SET stock=stock-%s WHERE product_id=1 AND stock>=%s", (qty, qty))
    c.commit(); cur.close(); c.close()

threads = [threading.Thread(target=deduct, args=(i, 2)) for i in range(10)]
[t.start() for t in threads]
[t.join() for t in threads]

# 验证库存非负
c = mysql.connector.connect(host="localhost", user="root", password="test123", database="testdb")
cur = c.cursor()
cur.execute("SELECT stock FROM products WHERE product_id=1")
assert cur.fetchone()[0] >= 0
print("并发测试通过 ✓")

为什么测试时需要跨表查

业务系统里，一张表几乎从不孤立存在。订单表存了 user_id 和 product_id，但没有用户名、没有商品名，要展示就得去用户表、商品表里「顺藤摸瓜」。测试时最常见的两类需求都依赖跨表能力：

  • 展示核对：页面上「订单-商品」是不是库里两张表对得上的；
  • 一致性验证：订单里的用户 ID，必须在用户表里真实存在，否则就是「孤儿记录」，是数据脏了的直接证据。

下面先建一个三表模型（users / orders / products），后面所有示例都基于它：

setup.sql — 三表建表 + 造数
CREATE TABLE users (
  id INT PRIMARY KEY,
  username VARCHAR(64) NOT NULL
);

CREATE TABLE products (
  id INT PRIMARY KEY,
  name VARCHAR(128) NOT NULL
);

CREATE TABLE orders (
  id INT PRIMARY KEY,
  user_id INT NOT NULL,          -- 注意：这里故意不加外键约束，模拟"裸关联"场景
  product_id INT NOT NULL,
  amount DECIMAL(10,2) NOT NULL
);

INSERT INTO users (id, username) VALUES (1, 'alice'), (2, 'bob');
INSERT INTO products (id, name) VALUES (101, '键盘'), (102, '鼠标');

-- 3 笔订单：user 1 买了键盘和鼠标，user 999（不存在的用户）买了鼠标
INSERT INTO orders (id, user_id, product_id, amount) VALUES
 (1, 1, 101, 89),
 (2, 1, 102, 25),
 (3, 999, 102, 25);

第 3 笔订单的 user_id = 999 是故意造的「脏数据」——用户表里没有 999 这个用户。它就是我们要抓的「孤儿记录」原型，后文会反复用到。

四种 JOIN，结果差在哪

先记一个口诀：INNER 只要两边都有的；LEFT 保住左边全部；RIGHT 保住右边全部；FULL 两边全保。逐一看：

INNER JOIN：只要两边都匹配上

join1.sql
SELECT o.id AS order_id, u.username, p.name AS product_name
FROM orders o
INNER JOIN users u ON o.user_id = u.id
INNER JOIN products p ON o.product_id = p.id;

结果只有 2 行（订单 1、订单 2）。订单 3 因为 user 999 在用户表里查不到，直接被「丢掉了」——INNER JOIN 的特点是匹配不上的记录整行消失，它不会告诉你「有记录对不上」，只会让结果看起来「少了几行」。

LEFT JOIN：保住左表全部

join2.sql
SELECT o.id AS order_id, o.user_id, u.username
FROM orders o
LEFT JOIN users u ON o.user_id = u.id;

结果 3 行全在，其中订单 3 那行的 username 是 NULL——左表（orders）的记录一条不丢，右表（users）匹配不上就用 NULL 占位。这正是「找孤儿记录」的核心机制，后面专门演示。

RIGHT JOIN：保住右表全部

join3.sql
SELECT u.username, o.id AS order_id
FROM users u
RIGHT JOIN orders o ON o.user_id = u.id;

效果等价于把上面 LEFT JOIN 的表左右调换一下。实际写的时候，大多数团队习惯统一用 LEFT JOIN + 调换表顺序，少记一种写法。

FULL JOIN：两边全保（MySQL 8 不支持原生写法）

MySQL 没有 FULL OUTER JOIN 关键字，等价写法是用 LEFT JOIN 和 RIGHT JOIN 做并集：

join4.sql — MySQL 里模拟 FULL JOIN
SELECT o.id AS order_id, o.user_id, u.username
FROM orders o LEFT JOIN users u ON o.user_id = u.id
UNION
SELECT o.id, o.user_id, u.username
FROM users u RIGHT JOIN orders o ON o.user_id = u.id
WHERE u.id IS NULL;
-- 上面这句 UNION 等价于：把"只有左没有右"和"只有右没有左"的记录全部捞出来
JOIN 类型左表独有记录右表独有记录两边都有
INNER丢丢保留
LEFT保留（右侧填 NULL）丢保留
RIGHT丢保留（左侧填 NULL）保留
FULL保留保留保留

测试场景：用 LEFT JOIN 抓「孤儿订单」

需求一句话：订单表里每个 user_id，都必须在用户表里存在。验证方法固定套路：LEFT JOIN + WHERE 右表主键 IS NULL。

find_orphans.sql
-- 找出"订单存在、但用户不存在"的记录
SELECT o.id AS orphan_order_id, o.user_id
FROM orders o
LEFT JOIN users u ON o.user_id = u.id
WHERE u.id IS NULL;

-- 同理，反向再查一遍：商品侧
SELECT o.id AS orphan_order_id, o.product_id
FROM orders o
LEFT JOIN products p ON o.product_id = p.id
WHERE p.id IS NULL;

跑第一条，会命中我们故意造的订单 3（user_id = 999）。第二条应该是空结果，说明商品侧数据干净。

Python 脚本：跑 JOIN 查询并输出差异

把上面的 SQL 包成可自动化的脚本，跑完直接告诉你「有没有孤儿、有几条」，可以无缝进 CI：

check_orphans.py
import pymysql

def get_conn():
    return pymysql.connect(
        host="127.0.0.1", port=3306,
        user="test_user", password="test_pwd",
        database="shop", charset="utf8mb4",
        cursorclass=pymysql.cursors.DictCursor,
    )

def find_orphan_orders():
    sql = """
        SELECT o.id AS orphan_order_id, o.user_id
        FROM orders o
        LEFT JOIN users u ON o.user_id = u.id
        WHERE u.id IS NULL
    """
    with get_conn() as conn, conn.cursor() as cur:
        cur.execute(sql)
        return cur.fetchall()

def main():
    orphans = find_orphan_orders()
    if orphans:
        print(f"❌ 发现 {len(orphans)} 条孤儿订单：")
        for row in orphans:
            print(f"   order_id={row['orphan_order_id']}, user_id={row['user_id']}（用户在 users 表里不存在）")
        return 1   # 用退出码 1 标记失败，方便 CI 判断
    print("✅ 没有发现孤儿订单，用户侧数据一致")
    return 0

if __name__ == "__main__":
    import sys
    sys.exit(main())

LEFT JOIN 找孤儿，前提是关联键本身不能是 NULL。如果订单表的 user_id 允许为空，NULL 也会出现在结果里，得先用 o.user_id IS NOT NULL 把这类记录排除掉，再判断「真孤儿」。
