安卓端的 AI Agent 运行时：Droy 如何把 Harness 塞进一个 APK

手机上的 Agent 一直有个绕不过去的前提：它得先连上一台电脑。电脑开着 ADB 守护进程和隧道，界面才能被外部读到；电脑一合盖，链路就断。套网页壳的方案能装上手机，却只能聊天，碰不到系统界面，也发不出点击。

Droy 换了个思路：把整套 DeepSeek Harness 运行时连同运行环境一起封进安装包，填好 API Key、拔掉数据线就能独立跑。按原文记录，它当时是 v0.0.3，AGPL-3.0 协议，356 个 star，由个人开发者维护，并非 DeepSeek 官方出品。版本号这么早，更适合当工程样本来读。

一、为什么安卓 Agent 总被一根数据线拴住

传统做法的耦合点在「谁持有执行能力」：ADB 方案里执行权在电脑侧的守护进程，手机只是被操控的终端；网页壳方案里干脆没有执行权。于是 Agent 的可用性会随一条线、一台机器、一个进程的存活状态波动。

搬进 APK 后，模型调用、任务规划、动作派发合并到一个进程。原文提到安装包已带好运行环境，手机不需要另装 Node、npm 或 DSH。少一层外部依赖，就少一类环境没配对导致的故障。

二、三层架构拆开，测试该盯住哪一层

原文把工程拆成交互层、引擎层、执行层。三层的不确定性来源不同，能施加的控制手段也不同。

层级核心组件负责的事测试该盯什么
交互层Kotlin 加 Jetpack Compose 客户端文字、语音、桌宠与任务空间急停入口是否随时可达
引擎层内嵌 DSH（原文记录为 0.2.1-rc.5）规划、长会话、Skills、插件、MCP 与模型调用动作序列、步数上限、上下文裁剪
执行层授权控制加 Android Use权限校验、急停、无障碍 / Shizuku / Root 派发越权负向用例、快照时效

引擎层最难测：模型是黑盒，工具是真实系统接口，时序还受手机性能影响。执行层最好测，它有明确的前置校验和拒绝路径，可以把每条限制写成负向用例。交互层最该验证的不是界面，而是急停能否在任意时刻生效——Agent 在后台切应用时，用户只剩这一个刹车。

团队若要照着做，建议先把引擎层的动作序列当成轨迹断言的对象：顺序、参数、终止各断一层，而不是只看最后一句回复。

三、坐标动作为什么必须绑快照和允许范围

「截张图猜坐标再瞎点」是真实事故来源：弹个广告、来条通知、页面自己滚一下，坐标就落到别处。Droy 在 android-use 模块给坐标动作加了两道约束：绑定当次的 snapshotId，限定允许范围；页面突变或目标有歧义时直接停手。

两个参数值得列为验收项：多指手势支持 2 到 5 条同步轨迹，android_sequence 一次串行 2 到 6 步。串联越长，中间任何一步落空，后面全歪。

登录和验证码交给本人，且用户答完后 Agent 仍要重新观察页面，不能把口头回复当成验证通过。翻译成测试语言就是：人工介入后必须重新取快照，后续动作绑在新快照上。对应两条负向用例——过期快照发起动作必须被拒绝；人工答复后不重新观察就继续动作，判失败。

四、NFC、红外和进程内存开放后，安全阀怎么验

硬件工具组最特别，也最容易出事。原文给出的边界本身就是一份验收清单。

能力域代表工具原文写明的限制
近场通信android_nfc、android_nfc_emulation贴卡认证密钥走 AndroidKeyStore；HCE 只跑本地状态机，不写原卡 UID，不执行模型临时生成的脚本
红外与无线android_infrared、android_wifi单段红外波形短于 2 秒；Wi-Fi 密码走本地 credentialRef，不回显给模型
进程内存android_process_memory、android_memory_write需 Root 与 64 位普通第三方应用；单次标量写入上限 8 字节；只碰已确认的私有可写非执行页

细节能看出作者踩过真机坑：卡模拟首版用 exact_apdu_state_v1，本地匹配完整 APDU 报文与状态流转，不碰厂商钱包安全元件；文档还写明内置 NFC 读不了 125 kHz 低频门卡。内存工具把会话绑在任务、包版本、UID、PID 与进程启动时间上，进程一重启旧引用即作废，写入前还要核对预期字节。大块数据走 dataRef 放私有目录分页读，上限 4 MiB。

测试重点不是能否读出内存，而是不该读时能否被挡住。这和常规APP 权限测试同思路：每条限制配一条拒绝用例，比如非 Root 调用内存工具应报错、写入超 8 字节应拒绝、进程重启后旧会话应失效。只测正向能力，等于没测安全阀。

五、什么场景现在还不该用它

原文列了四条现实边界。成熟度：v0.0.3，仅支持 Android 11 以上、ARM64 与竖屏，不适合压生产关键流程。保活：国产系统易强杀引擎，需要持续后台运行、电池不受限、最近任务加锁。权限门槛：通知静默接管与进程内存读写必须有 Root。演示口径：仓库海报里的对话与清单属于本地演示数据，真实稳定度取决于配置的视觉模型与当前界面。

安装有两条路。一是装签名 APK，从 Release 下载 ARM64 包，核对 SHA-256 与签名指纹。二是交给电脑脚本跑 tools/setup.py 的 scan、plan、apply、verify 四步，看过 approvalDigest 才真动手机；API Key 始终只在手机本地手填，不进日志。

它的价值不在今天能替你点外卖，而在把权限分级、离线语音、本地记忆、射频约束、签名校验写成可检查的规格。对做移动端 Agent 的团队，App 自动化的下一步不是让模型更聪明，而是让每条「不许干什么」都能被测试证明。
