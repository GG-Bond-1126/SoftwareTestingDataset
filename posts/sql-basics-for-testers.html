基础应用：第一个 SQL 验证

python
import mysql.connector

conn = mysql.connector.connect(host="localhost", port=3306, user="root", password="test123", database="testdb")
cur = conn.cursor()
cur.execute("INSERT INTO users (name, email) VALUES (%s, %s)", ("测试", "t@e.com"))
conn.commit()
cur.execute("SELECT * FROM users WHERE name = %s", ("测试",))
assert cur.fetchone() is not None
print("基础验证通过 ✓")
cur.close(); conn.close()

项目进阶：并发测试 + 数据一致性

python
import mysql.connector, threading

def deduct(uid, qty):
    c = mysql.connector.connect(host="localhost", user="root", password="test123", database="testdb")
    cur = c.cursor()
    cur.execute("UPDATE products SET stock=stock-%s WHERE product_id=1 AND stock>=%s", (qty, qty))
    c.commit(); cur.close(); c.close()

threads = [threading.Thread(target=deduct, args=(i, 2)) for i in range(10)]
[t.start() for t in threads]
[t.join() for t in threads]

# 验证库存非负
c = mysql.connector.connect(host="localhost", user="root", password="test123", database="testdb")
cur = c.cursor()
cur.execute("SELECT stock FROM products WHERE product_id=1")
assert cur.fetchone()[0] >= 0
print("并发测试通过 ✓")

什么是 SQL，为什么测试工程师必须懂

SQL（Structured Query Language，结构化查询语言）是跟数据库打交道的「普通话」。你在页面上点「提交订单」，后台大概率会发生这样一串事：先查用户表确认身份，再写订单表、扣库存表、更新余额表。测试时你要回答「数据到底写没写对、写对了几条」，绕不开 SQL。

一个常见的误区是：会写 SELECT * FROM orders 就算会 SQL 了。实际上，会查只是入门，会按条件查、会对比、会统计，才是测试真正需要的能力。下面所有场景都假设你已经连上了一个 MySQL 实例，并且建好了一张用户表、一张订单表：

setup.sql — 建库建表造数
-- 创建数据库并切换
CREATE DATABASE IF NOT EXISTS shop DEFAULT CHARACTER SET utf8mb4;
USE shop;

-- 用户表：id 主键，balance 余额
CREATE TABLE users (
  id INT PRIMARY KEY AUTO_INCREMENT,
  username VARCHAR(64) NOT NULL,
  balance DECIMAL(10,2) NOT NULL DEFAULT 0,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- 订单表：user_id 关联 users，amount 金额
CREATE TABLE orders (
  id INT PRIMARY KEY AUTO_INCREMENT,
  user_id INT NOT NULL,
  amount DECIMAL(10,2) NOT NULL,
  status TINYINT NOT NULL DEFAULT 0,   -- 0 待支付 1 已支付 2 已退款
  paid_at DATETIME NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- 造几条测试数据
INSERT INTO users (username, balance) VALUES ('alice', 100), ('bob', 50), ('carol', 200);
INSERT INTO orders (user_id, amount, status, paid_at) VALUES
 (1, 30, 1, NOW()),
 (1, 10, 0, NULL),
 (2, 20, 2, NOW()),
 (3, 80, 1, NOW());

建议在测试环境里专门建一个空库反复练习，别直接在开发共用的库里折腾。所有练习语句都可以安全地重跑。

6 个高频测试场景，逐个拆 SQL

场景 ①：查某用户的所有订单

需求：「帮我看看用户 alice 名下有几笔订单、什么状态。」 这是最基础的「按条件查」，核心是 WHERE 等值条件：

query1.sql
-- 先拿用户的 id（测试里一般先用用户名定位，再按 id 查业务表）
SELECT id FROM users WHERE username = 'alice';
-- 结果：1

-- 用这个 id 查所有订单，按时间倒序
SELECT * FROM orders WHERE user_id = 1 ORDER BY created_at DESC;

场景 ②：验证某笔退款是否到账

用户投诉「退款说成功了但没收到钱」。要验证，需要同时看订单状态和用户余额是否对得上：

query2.sql
-- 查退款订单本身
SELECT id, user_id, amount, status, paid_at FROM orders WHERE status = 2;

-- 再查这个用户的余额，确认退款金额已加回
SELECT balance FROM users WHERE id = 2;

把两边的数人工核对一遍（或者用下一节的 Python 脚本自动断言），就能判断退款链路是否真的闭环。

场景 ③：统计某天的注册用户数

「今天注册了多少新用户？」 考察点有两个：时间范围写法 和 聚合函数 COUNT：

query3.sql
-- 统计 2026-11-23 全天（含首尾）注册的账号数
SELECT COUNT(*) AS cnt
FROM users
WHERE created_at BETWEEN '2026-11-23 00:00:00' AND '2026-11-23 23:59:59';

时间边界是最容易踩坑的地方。BETWEEN 是「两头都算」，写 00:00:00 到 23:59:59 其实漏掉了 23:59:59 到 24:00:00 之间的那几毫秒。更稳妥的写法是 created_at >= '2026-11-23' AND created_at < '2026-11-24'，左闭右开，天然没有缝隙。

场景 ④：找出重复数据

「同一个邮箱被注册了好几次，帮我列出来。」 用 GROUP BY + HAVING，按分组后的统计结果再过滤一次：

query4.sql
-- 假设 users 表有 email 字段，找出出现次数 > 1 的邮箱
SELECT email, COUNT(*) AS cnt
FROM users
GROUP BY email
HAVING COUNT(*) > 1;

场景 ⑤：检查外键完整性（孤儿记录）

「订单里的 user_id，是不是都能在用户表里找到？」 这就是典型的 LEFT JOIN 找「对不上」的记录，下一篇文章会专门展开，这里先给结论式写法：

query5.sql
-- 订单存在、但用户不存在（users 侧为 NULL），说明是孤儿订单
SELECT o.id, o.user_id
FROM orders o
LEFT JOIN users u ON o.user_id = u.id
WHERE u.id IS NULL;

场景 ⑥：验证数据迁移后是否丢数据

从老库迁到新库后，最朴素的校验就是「两边行数、两边关键统计值是否一致」：

query6.sql
-- 老库
SELECT COUNT(*), SUM(amount), MAX(created_at) FROM orders;
-- 新库（同一句 SQL 再跑一遍）
SELECT COUNT(*), SUM(amount), MAX(created_at) FROM orders;
-- 三个值全部相等，才能初步判定没丢数据；进一步可以拿两边的 id 集合做对比

常用 WHERE 条件写法速查

测试写 SQL 时反复用到的条件就这几种，记熟基本够用：

写法含义示例
=精确等值status = 1
IN (...)命中列表中的任意一个status IN (1, 2)
BETWEEN a AND b闭区间范围内amount BETWEEN 10 AND 100
LIKE模糊匹配，% 是任意多字符username LIKE 'a%'
IS NULL / IS NOT NULL判空（不能用 = NULL）paid_at IS NULL
AND / OR / NOT组合条件，注意加括号控制优先级(status = 1 OR status = 2) AND user_id = 1

完整案例：用 Python 连接 MySQL 跑 SQL 并断言

测试脚本里跑 SQL，标准姿势是：连库 → 执行查询 → 取结果 → 断言 → 清理。下面这段代码可以直接跑，它验证「用户 1 的已支付订单金额合计 = 30」：

verify_orders.py — 连接 MySQL 执行 SQL 并断言
import pymysql
import sys

def main():
    # 连接 MySQL（按自己环境改 host/port/账号）
    conn = pymysql.connect(
        host="127.0.0.1",
        port=3306,
        user="test_user",
        password="test_pwd",
        database="shop",
        charset="utf8mb4",
        cursorclass=pymysql.cursors.DictCursor,  # 让查询结果可以直接按字段名取
    )
    try:
        with conn.cursor() as cur:
            # 先造一条已支付订单，保证测试数据是"自造自清"的
            cur.execute(
                "INSERT INTO orders (user_id, amount, status, paid_at) VALUES (1, 15, 1, NOW())"
            )
            conn.commit()
            cur.execute("SELECT LAST_INSERT_ID() AS new_id")
            new_id = cur.fetchone()["new_id"]

            # 核心断言：用户 1 的已支付订单金额合计应该是 30 + 15 = 45
            cur.execute(
                """
                SELECT SUM(amount) AS total
                FROM orders
                WHERE user_id = 1 AND status = 1
                """
            )
            total = cur.fetchone()["total"]
            print(f"用户 1 已支付订单金额合计 = {total}")
            assert total == 45, f"断言失败：期望 45，实际 {total}"
            print("✅ 断言通过")

        # 清理：删掉自己造的数据，别污染别人
        with conn.cursor() as cur:
            cur.execute("DELETE FROM orders WHERE id = %s", (new_id,))
            conn.commit()
    finally:
        conn.close()
    return 0

if __name__ == "__main__":
    sys.exit(main())

跑通这一段之后，你已经具备了「自己造数、自己查数、自己下结论」的完整能力。剩下的工作，就是把这套姿势套进你手上的真实表里。

把本文 6 个场景当成一张 checklist：新接手一个项目时，先对着真实表把 ①③⑤⑥ 各写一遍，基本就能摸清这张库的数据长什么样、哪些字段是关键字段了。
